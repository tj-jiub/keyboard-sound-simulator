# 해커톤 프로젝트 인수인계 문서

> 이 문서는 기획 대화(약 20턴)의 결과를 정리한 것이다. 코드는 아직 한 줄도 작성하지 않았다.
> 다음 작업자는 아래 "결정 사항"을 다시 논의하지 말고 **그대로 구현**하면 된다.
> 이 저장소(`keyboard-sound-simulator`)는 Electron 키보드 앱 + 정적 랜딩(`docs/`)이며 **이번 프로젝트와 무관하다.** 새 프로젝트는 `hackathon/` 아래 또는 별도 디렉터리에 만든다. `docs/`는 Vercel/Cloudflare 정적 배포 출력이므로 그 안에 문서를 두지 않는다.

## 0. 상황
- 3시간 해커톤, 2~3명, 자유 주제, 결과물은 **배포 URL이 있는 웹 서비스**
- 사용자 선호: 답변은 짧고 핵심부터. 여러 단계가 필요하거나 결과가 크게 달라질 수 있으면 시작 전에 질문. 확인하지 못한 내용은 확인하지 못했다고 말하기
- 서비스 이름: **보류**

## 1. 결정 사항 (확정)
1. **주제:** 향수. 옷 추천 안은 폐기
2. **문제 정의:** 향 표현이 주관적이어서 비교 기준이 없고, 구매자·직원 모두 "A와 비슷한 향수"를 확신 있게 찾거나 설명하지 못한다
3. **제품 방향:** 성수 같은 붐비는 매장에서, 원하는 향을 입력하면 **그 매장 재고 중** 시향할 후보 3~5개를 보여준다 (모든 향수를 맡아볼 필요 없게)
4. **주 사용자:** 매장 안 구매자(모바일, QR 진입). 직원은 같은 화면으로 응대하는 보조 사용자
5. **차별화:** 매장 재고+진열 위치, 시향 후 피드백 1탭(실제 맡아본 사람들의 유사도), 매장 현장 흐름. 큰 커뮤니티는 만들지 않는다
6. **데이터:** scento 데이터셋(CC-BY-4.0) + 매장 재고 직접 입력(manual). Fragrantica는 사용하지 않는다
7. **재고:** 매일 마감 후 확인 가능 → CSV 업로드로 갱신. 화면에 "어제 마감 기준" 표시
8. **한글 검색:** 별칭 매핑 사용 (`ko_aliases.json`, 초안)

## 2. 논의 과정에서 나온 근거 (왜 이렇게 정했나)
- **온라인 정보 사이트로는 AI(ChatGPT 등)와 경쟁하기 어렵다.** 대신 AI가 모르는 것(특정 매장 재고·진열, 시향 후 실제 평가, 매장 현장 흐름)에 집중한다
- **문제 출처:** 사용자가 Kinfolk 매장 직원의 경험(고객이 "특정 향수랑 비슷한 거 있나요?"라고 물을 때 답하기 어려움)을 직접 들었다. 구매자 쪽은 "유튜브 리뷰마다 말이 달라 헷갈린다"는 **전해 들은 내용**이다. 사용자 본인은 향수 구매자가 아니다 → 발표용으로 실제 리뷰 사례와 인터뷰 보강 필요
- **레퍼런스 Scentpedia** (https://scentpedia.co.kr): 한국어 향수 위키. 향수 6,000여 종, 향료 311종, 취향 분석(좋아하는 향수 선택 → 노트 기반 매치율 추천), 이상형 월드컵, 향수장, 카드 이미지 저장, 커뮤니티, 쿠팡 파트너스·네이버 쇼핑 링크 수익. 커뮤니티는 렌더링해서 확인했는데 "오늘 뭐 뿌렸어요" 기록 글이 몇 건(2026년 6월자)뿐이었고 질문 글은 없었다. 즉 **온라인 탐색형이고 매장 현장은 다루지 않는다**
- **레퍼런스 Fragrantica** (fragrantica.ru): 접속이 403으로 차단되어 **내용을 확인하지 못했다.** 이용약관·API도 확인하지 못했다. 제3자 설명에 따르면 공식 API가 없고 스크래퍼 서비스가 존재한다 → 사용하지 않기로 함

## 3. 데이터셋 조사 결과 (직접 내려받아 검증)
- 소스: https://huggingface.co/datasets/scento/perfume-database (CC-BY-4.0, 2026-10-29 스냅샷)
- 파일: `perfumes.csv`(1,479행), `houses.csv`(160), `materials.csv`(420), `perfumes.jsonl`, `datapackage.json`
- 다운로드: `curl -L -o perfumes.csv https://huggingface.co/datasets/scento/perfume-database/resolve/main/perfumes.csv` (**`-L` 필수**, 리다이렉트됨)
- `perfumes` 컬럼: id, name, house_id, house, year, perfumers, concentration, family, secondary_family, character, seasons, times_of_day, top_notes, heart_notes, base_notes, notes, description, popularity_rank, url (리스트는 `; `로 구분)
- `materials` 컬럼: id, name, aliases, material_family, origin, smell, url
- 피라미드 완비 1,388/1,479(94%), 노트 12,448개가 향료 사전에 **100% 매핑**
- 한계: 영어 전용, 한국 브랜드 부재(탬버린즈·논픽션·샤넬 0개), Armaf 189·Afnan 53 등 중동 계열 편중, 연도·조향사는 거의 비어 있음, 데이터의 원 출처는 독립 검증하지 못함
- **출처 표기 필수:** "Scento — https://www.scento.com/perfume-database"

## 4. 한글 별칭 (`ko_aliases.json`)

# 기능 명세 v0.2 (서비스 이름 보류)

> v0.1 대비 변경: 데이터 확정(scento), 한글 별칭 매핑 추가, 유사도 계산 구체화, 매일 마감 후 재고 갱신 흐름 추가

## 1. 한 줄 정의
붐비는 매장에서 모든 향수를 맡지 않아도 되도록, **원하는 향을 입력하면 이 매장 재고 중 시향할 후보 3~5개를 추려 주는 웹 서비스**

## 2. 문제 정의
> 향수의 향은 사람마다 다르게 표현되어 비교 기준이 없다. 그래서 구매자와 매장 직원 모두 "A와 비슷한 향수"를 확신 있게 찾거나 설명하지 못한다.

- 직원 사례: Kinfolk 직원이 고객의 "특정 향수랑 비슷한 거 있나요?"에 답하기 어려웠다 (직접 들은 사례)
- 구매자 사례: 유튜브 리뷰마다 향 표현이 달라 헷갈린다 (전해 들은 내용, 발표용 실제 리뷰 사례 2~3개 수집 필요)
- 구매자 본인이 향수 고객은 아니므로 인터뷰 3~5건으로 보강 필요

## 3. 사용자와 차별화
- 주 사용자: 매장 안 구매자(모바일). 보조: 같은 화면을 보고 응대하는 직원
- 온라인 정보만으로는 AI와 경쟁하기 어렵다. 우리의 자산은 세 가지다.
  1. 매장 재고 + 진열 위치 (AI가 모르는 데이터)
  2. 시향 후 피드백 (실제로 맡아본 사람들의 유사도)
  3. 매장 현장 사용 흐름 (QR 한 번)

## 4. 범위
| 우선순위 | 기능 |
|---|---|
| P0 | QR 진입, 향수 검색(영/한), 재고 기반 유사 후보, 후보 카드(차이 한 줄), 시향 피드백 1탭, 재고 갱신(CSV) |
| P1 | 방향 조절 슬라이더, 말로 묘사 입력(LLM), 시향 순서, 직원 보여주기 모드 |
| P2 | 재고 관리 화면, 다중 매장, 브랜드 제휴, 구매 링크 |
| 제외 | 로그인, 게시판형 커뮤니티, 결제 |

## 5. 사용자 흐름
1. 매장 QR → `/s/{매장코드}`
2. 좋아하는 향수 검색 (한글/영문)
3. 후보 카드 3~5개 (비슷한 이유, 다른 점, 진열 위치)
4. 직원에게 보여주거나 직접 시향
5. 맡아본 뒤 "비슷했어요 / 달랐어요" 1탭

## 6. 기능 상세와 완료 기준

**F1. 향수 검색 (P0)**
- 영문 이름·브랜드와 한글 별칭 모두 검색 (아래 8장)
- 정규화: 소문자, 공백·특수문자 제거 후 비교
- 완료: "상탈33", "상탈 33", "santal33" 모두 Le Labo Santal 33이 나온다. 없는 이름은 "찾지 못했어요" + 영문 검색 안내

**F2. 유사 후보 추천 (P0)**
- 입력 향수와 **해당 매장 재고**를 비교해 상위 3~5개 (입력 향수 자체 제외)
- 완료: 재고에 없는 향수는 절대 노출되지 않는다. 재고가 3개 미만이면 있는 만큼만 보여준다

**F3. 후보 카드 (P0)**
- 브랜드·이름, 노트 피라미드, 유사도, 한 줄 설명, **A와 다른 점 한 줄**, 진열 위치, 데이터 출처
- 완료: 모바일 한 화면에 카드가 보이고 설명이 한 줄 안에 들어간다

**F4. 시향 피드백 (P0)**
- 카드마다 "맡아봤어요" → 비슷했어요 / 달랐어요 (익명, 같은 세션·같은 쌍 1회)
- 집계 3건 이상이면 "맡아본 N명 중 M명이 비슷하다고 했어요", 미만이면 "아직 데이터가 부족해요"
- 완료: 새로고침 후에도 집계가 유지된다

**F5. 재고 갱신 (P0, 신규)**
- 매일 마감 후 직원이 재고를 확인한다는 전제. 화면 없이 **CSV 업로드(또는 시트 연동) 한 번**으로 갱신
- 컬럼: `perfume_id, shelf, in_stock`. 데이터셋에 없는 향수는 `manual` 행으로 직접 입력 (노트는 사전 표기 사용)
- 완료: 업로드 후 새 재고로 추천이 바뀌고, `updated_at`이 매장 화면에 "오늘 마감 기준" 등으로 표시된다
- 당일 품절 가능성이 있으므로 "재고는 어제 마감 기준, 직원 확인 필요" 문구를 둔다

**F6. 방향 조절 (P1)** 더 달게/덜 무겁게/더 우디하게 → 향료 계열 가중치를 이동해 재계산

**F7. 말로 묘사 입력 (P1)** LLM이 묘사를 향료 계열 벡터로 변환 후 F2 호출. 실패 시 이름 검색으로 폴백

**F8. 시향 순서·직원 모드 (P1)** 가벼운 향 → 무거운 향 순 번호, 큰 글씨·노트·위치 위주 화면

## 8. 한글 별칭 매핑 (신규)
- 초안 파일: `ko_aliases.json` — 브랜드 160개 전체 + 인기 상위 향수 150개
- **모델 지식으로 작성한 초안이며 한국 판매처와 대조 검증하지 않았다.** 사용 전 검토 필요
- 검증 결과: 모든 id가 데이터셋에 존재, 별칭 충돌 없음 (자동 확인)
- 검색 순서: ① 별칭 정규화 매칭 → ② 영문 부분 일치 → ③ (P1) LLM으로 후보 해석
- 커버 범위 밖(나머지 약 1,330개)은 영문 검색으로 접근. 매장 재고의 향수는 **재고 등록 시 한글 별칭을 같이 입력**하는 것을 권장
- 한국 브랜드(탬버린즈, 논픽션 등)와 Kinfolk 취급 향수는 `manual` 입력으로 별도 추가

## 9. 유사도 계산 (구체화)
1. 향수별 **계열 벡터**: 노트를 `material_family`(Floral, Gourmand, Wood, Citrus, Musk 등 약 15개)로 집계. 피라미드 위치 가중치(초기값 top 0.2 / heart 0.35 / base 0.45)를 곱함
2. 유사도 = 0.6 × 계열 벡터 코사인 + 0.2 × 노트 자카드 + 0.2 × (family 일치, character 태그 자카드)
3. 가중치는 **초기 추정값**이다. 알려진 쌍(예: Aventus ↔ Club de Nuit Intense)으로 상식 점검하며 조정한다
4. "다른 점" 문장: 두 벡터에서 차이가 큰 상위 2개 계열 + character 태그 차이로 **규칙 기반** 생성. P1에서 LLM은 문장 다듬기만 담당(수치는 규칙에서만 사용)
5. 피드백 반영: `최종 = 노트 유사도 × (1−w) + 시향 유사 비율 × w`, w는 건수에 따라 증가 (예: 10건에서 0.3 상한)
6. 피드백 쌍이 적을 때는 노트 유사도만 사용

## 11. 기술 방향 (제안)
- 정적 프론트 + 서버리스 함수 (저장소의 Cloudflare/Vercel 설정 활용 가능)
- 데이터셋은 빌드 시 JSON으로 변환해 번들 (약 1,479행으로 작음), 피드백·재고만 경량 DB(KV 또는 D1)
- 유사도 계산은 서버리스 함수 1개 또는 클라이언트
- 모바일 우선

## 12. 데모 성공 기준
- 검색 → 후보 → 카드 → 피드백까지 60초 내 끊김 없이 시연
- 같은 입력이라도 **재고가 다르면 결과가 달라진다**를 보여준다
- 피드백 몇 건 입력 후 "맡아본 사람들 기준" 수치가 바뀌는 것을 보여준다
- 데모에 실제 Kinfolk 재고를 못 쓰면 가상 재고로 하고 그렇게 밝힌다

## 13. 수익 서사 (발표용, 검증 전)
1. 초기: 개인은 무료, 구매처 제휴 링크 (Scentpedia가 쿠팡 파트너스·네이버 쇼핑 링크 사용)
2. 핵심: 매장·팝업 구독 (재고 기반 안내, 응대 부담 감소)
3. 확장: 시향 샘플 세트 연계, 브랜드 신제품 시향 유도
- 구체적인 가격·시장 규모·전환 효과는 확인된 데이터가 없다. 가설로 표현한다

## 14. 위험과 가정
| 위험 | 대응 |
|---|---|
| 매장 재고·협조 | Kinfolk에서 매일 마감 후 CSV 제공 가능 여부 확인 (가능하다고 답함). 불가 시 가상 재고 |
| 노트 유사도 ≠ 실제 체감 | "참고용, 시향으로 최종 확인" 문구 + 피드백 루프로 보정 |
| 한국 브랜드 데이터 부족 | manual 입력, 한글 별칭 확장 |
| 별칭 초안 오류 | 출시 전 검토, 오류 신고 링크 |
| 데이터 원 출처 | CC-BY 표기 유지, 상업화 전 재검토 |
| 구매자 페인 미검증 | 인터뷰·리뷰 사례 수집 |
